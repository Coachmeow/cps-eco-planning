# สไตล์การทำงานที่เจ้าของโครงการต้องการ

> ไฟล์นี้มีไว้ให้ AI ผู้ช่วย (Claude Code) หรือผู้พัฒนาคนใหม่อ่าน เพื่อให้ทำงานเข้ากันได้เร็ว

## เจ้าของโครงการ

**Dew** — ดูแลทีม M&S ที่ SCI Eco Services (สาขาสระบุรี)

- เชี่ยวชาญเนื้องานจริง: การตรวจวัดสิ่งแวดล้อม การจัดตารางเครื่องมือ การบริหารทีมภาคสนาม
- คุ้นเคยกับการทำงานบน Excel — ระบบใหม่ต้องให้ความรู้สึกใกล้เคียง (ตาราง grid)
- ทีมพูดไทย — **UI ต้องเป็นภาษาไทยทั้งหมด**
- ทำตามขั้นตอนและรันคำสั่งบน command line ได้ แต่ไม่ใช่โปรแกรมเมอร์

## วิธีตอบที่ต้องการ

1. **อธิบายเหตุผลก่อนลงมือเขียนโค้ด** — ไม่ใช่โยนโค้ดมาเฉยๆ
2. **มีหลายทางเลือก ให้เทียบข้อดีข้อเสียก่อน** แล้วค่อยแนะนำว่าควรเลือกอันไหนเพราะอะไร
3. **เขียนโค้ดที่ใช้งานได้จริง** ไม่ใช่โค้ดตัวอย่างครึ่งๆ กลางๆ
4. **ถามก่อนเมื่อไม่แน่ใจ** — โดยเฉพาะเรื่องที่กระทบข้อมูลจริงหรือกระทบผู้ใช้
5. เวลาเจอปัญหาให้บอกตรงๆ พร้อมเหตุผล ไม่ต้องเออออตาม

## ข้อห้ามในการทำงาน

- ❌ **ห้ามรัน dev server ในเครื่องแล้วต่อกับฐานข้อมูล production** (ไฟล์ `.env` ในเครื่องเป็นค่าหลอก ไม่มีฐานข้อมูลจริงในเครื่อง)
- ❌ **ห้าม push ขึ้น master โดยไม่ขออนุญาต** เพราะ push = deploy ขึ้นระบบจริงทันที
- ❌ ห้ามรัน `prisma db seed` กับข้อมูลจริง (ล้างข้อมูลทั้งหมด)

## วิธีตรวจงานก่อน commit

รัน 2 คำสั่งนี้ให้ผ่านก่อนเสมอ (ตรวจในเครื่องได้ ไม่ต้องต่อฐานข้อมูล):

```bash
npx tsc --noEmit
npx next build
```

## หมายเหตุทางเทคนิคที่มักเจอ

- Git Bash บน Windows แสดงภาษาไทยเป็นตัวอักษรเพี้ยน (mojibake) — ตัวไฟล์ปกติดี เป็นปัญหาการแสดงผลบนหน้าจอเท่านั้น ให้ใช้เครื่องมืออ่านไฟล์แทนการ `cat`
- ปรัชญาของระบบคือ **"เตือน ไม่บล็อก"** — เช่น จองเครื่องซ้อนกันได้แต่ต้องขึ้นคำเตือนให้เห็นชัด
