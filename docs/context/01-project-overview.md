# ระบบนี้คืออะไร

**Eco Planning System** — ระบบวางแผนงานและจัดการเครื่องมือของ **SCI Eco Services Co., Ltd.** (สาขาสระบุรี) ทีม Maintenance & Support (M&S) / Envi Service

## ทำไมถึงสร้าง

ทดแทนไฟล์ Excel 2 ไฟล์ (ตารางเครื่องมือ + แผนพนักงาน) ที่มีปัญหา:

- ไม่มีการเตือนงานชนกัน ต้องไล่ดูเอง
- ติดตามงานข้ามทีมไม่ได้
- คำนวณ Utilization ด้วยมือ
- ไม่มีการเตือนสิทธิ์เข้าไซต์ใกล้หมดอายุ
- ไฟล์ล็อกเมื่อมีคนเปิดค้าง แก้พร้อมกันไม่ได้

## เทคโนโลยี

Next.js (App Router) + TypeScript + Tailwind CSS + PostgreSQL + Prisma
Hosting: **Railway.app** (ทั้งเว็บและฐานข้อมูล)

## 6 ทีมบริการ

| โค้ด | ทีม |
|---|---|
| ST | Stack |
| AMB | Ambient |
| WP | Workplace |
| CEMS | CEMS |
| WT | Water |
| LOG | Logistic (ทีมสนับสนุน/แอดมิน — ไม่ออกหน้างาน) |

พนักงานภาคสนามประมาณ 28–30 คน

## กติกาสำคัญที่ต้องเข้าใจก่อนแก้โค้ด

1. พนักงานมีทีมหลัก (primary team) ประจำ แต่ทำงานข้ามทีมในวันเดียวกันได้ **ถ้าเป็นไซต์เดียวกัน**
2. **งานคนชนกัน** = คนเดียวกัน วันเดียวกัน แต่ **คนละไซต์** (ถ้าไซต์เดียวกันแต่คนละบริการ = ไม่ถือว่าชน)
3. **เครื่องมือชนกัน** = เครื่องเดียวกัน ถูกจอง 2 งานในวันเดียวกัน
4. `estimatedDays` → ระบบเติมวันถัดไปในตารางให้อัตโนมัติ (งานหลายวันมีวันแม่ 1 + วันลูก n)
5. **Utilization นับตามประเภทงานที่ทำจริง** (serviceTypeId) ไม่ใช่ทีมหลักของพนักงาน
6. **ทีม LOG ไม่ถูกนับใน Capacity/Utilization** (ควบคุมด้วย flag `ServiceTeam.isFieldTeam`) เพราะเป็นงานแอดมินในออฟฟิศ แต่ยังลงแผนในปฏิทินได้ปกติ
