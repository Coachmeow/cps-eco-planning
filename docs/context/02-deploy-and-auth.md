# การ Deploy · สิทธิ์ผู้ใช้ · ตัวแปรลับ

## Deploy ทำงานอย่างไร

**push ขึ้น branch `master` = deploy ขึ้น production ทันที** ไม่มีขั้นตอนกดปุ่มอะไรเพิ่ม
Railway จะดึงโค้ดใหม่ แล้วรันตามที่กำหนดใน `railway.json`:

1. `prisma db push --accept-data-loss` — ปรับโครงสร้างฐานข้อมูลให้ตรงกับ `prisma/schema.prisma`
2. `node scripts/bootstrap.cjs || true` — สคริปต์ตั้งค่าเริ่มต้น (รันซ้ำได้ ไม่ลบข้อมูล)
3. `npm start` — เปิดเว็บ

> ⚠️ **ห้ามรัน `npx prisma db seed` กับข้อมูลจริง** — คำสั่งนั้นล้างข้อมูลทั้งหมด (`deleteMany`)

### bootstrap.cjs ทำอะไรบ้าง

รันทุกครั้งที่ deploy และออกแบบให้ **รันซ้ำได้โดยไม่พัง** (idempotent) หน้าที่หลัก:
สร้างบัญชีแอดมิน · สร้างบัญชีพนักงานที่ยังไม่มี · ตั้งลำดับทีม · ตั้งทีมสนับสนุน (LOG) ·
นำเข้าอะไหล่/รูป/ข้อมูลพนักงานครั้งแรก · ซิงก์แผน Cal ให้ตรงกับใบงาน · ย้ายสิทธิ์ CEMS แบบเก่ามาแบบใหม่

## ตัวแปรลับบน Railway (Variables)

ตั้งที่ Railway → เลือก service → แท็บ **Variables** ตัวแปรเหล่านี้ **ไม่ได้อยู่ในโค้ด** และหายไปไม่ได้:

| ตัวแปร | ใช้ทำอะไร | ถ้าไม่ตั้ง |
|---|---|---|
| `DATABASE_URL` | ที่อยู่ฐานข้อมูล PostgreSQL | เว็บใช้งานไม่ได้เลย |
| `AUTH_SECRET` | กุญแจเซ็น cookie ล็อกอิน | ใช้ค่าเริ่มต้นที่ไม่ปลอดภัย |
| `CEMS_QR_PIN` | รหัส 6 หลักกันคนนอกเข้าหน้า QR | **หน้า QR เปิดโล่ง ไม่ถามรหัส** |

## โครงสร้างสิทธิ์ผู้ใช้

### สิทธิ์ระบบหลัก (4 ระดับ)

| Role | ทำอะไรได้ |
|---|---|
| **ADMIN** | ทุกอย่าง + กำหนดสิทธิ์คนอื่น |
| **MANAGER** | วางแผน + จัดการข้อมูล (ลบเครื่องมือที่ซื้อไม่ได้ ลบได้เฉพาะเครื่องเช่า) |
| **MAINTENANCE** | เปลี่ยนสถานะเครื่องมือ · เมนูจัดการข้อมูล |
| **GENERAL** | ดูแผนอย่างเดียว |

### สิทธิ์โมดูล CEMS (แยกอีกชั้น)

| CemsRole | ทำอะไรได้ |
|---|---|
| **NONE** | เข้าโมดูล CEMS ไม่ได้ |
| **USER** | ดูทุกหน้า + บันทึกงานประจำวัน (ขอเบิกอะไหล่ · บันทึกความดันแก๊ส · ย้าย/ซ่อม/PM เครื่อง) |
| **ADMIN** | เพิ่มเติมจาก USER: อนุมัติคำขอเบิก · ลบข้อมูล · จัดการทะเบียน/แผน · ตัดสต็อกตรง |

> ADMIN ของระบบ = CEMS Admin โดยอัตโนมัติเสมอ

### หลักความปลอดภัยของโปรเจกต์นี้

**API คือด่านจริง** — ทุก route ตรวจสิทธิ์ด้วย `requireRole()` / `requireCems()` / `requireCemsAdmin()`
ส่วนการซ่อนปุ่มใน UI (ผ่าน hook `useMe`) เป็นแค่ความสะดวก **ไม่ใช่ระบบความปลอดภัย** —
ถ้าจะเพิ่มฟีเจอร์ใหม่ ต้องใส่การตรวจสิทธิ์ที่ API เสมอ อย่าพึ่งการซ่อนปุ่มอย่างเดียว

**เทคโนโลยี:** รหัสผ่านเข้ารหัสด้วย scrypt (`node:crypto`) + session cookie แบบ JWT (`jose`)
`lib/auth-edge.ts` = ใช้ได้ใน middleware · `lib/auth.ts` = ฝั่ง server เท่านั้น

## หน้า QR สาธารณะ (ไม่ต้องล็อกอิน)

| URL | ใช้ทำอะไร |
|---|---|
| `/a/[token]` | QR ติดเครื่อง CEMS — แจ้งปัญหา/PM/ย้ายที่/ส่งซ่อม |
| `/g/[token]` | QR ติดถังแก๊สมาตรฐาน — บันทึกความดัน/แจ้งหมด/แจ้งส่งคืน |
| `/p/[token]` | QR ติดชั้นอะไหล่ — ขอเบิกอะไหล่ (รอ CEMS Admin อนุมัติ) |
| `/m/[token]` | QR ติดรถ — บันทึกเลขไมล์ |

ทั้ง 3 หน้าแรกถูกกันด้วยรหัสรวม `CEMS_QR_PIN` (ถ้าตั้งไว้) ผู้ใช้กรอกครั้งเดียว จำไว้ 7 วันในเครื่องนั้น
รหัสไม่ได้อยู่ใน URL — ส่งลิงก์ต่อให้คนอื่น ปลายทางต้องกรอกรหัสเองอยู่ดี

## จุดกู้คืน (Restore point)

มี git tag ไว้ย้อนกลับเมื่อของใหม่พัง:
- `v1` + branch `v1-stable` — เวอร์ชันก่อนเพิ่มระบบล็อกอิน
- `ui-pre-charts` — เวอร์ชันก่อนปรับ UI Dashboard เป็นกราฟชุดใหม่

ย้อนกลับด้วย `git reset --hard <ชื่อ tag>` (ระวัง: ทำแล้วโค้ดใหม่หายหมด ควรปรึกษาก่อน)
