# คู่มือกู้คืนโครงการ — Eco Planning System

**สำหรับกรณี:** คอมพัง · เปลี่ยนเครื่องใหม่ · ส่งงานให้คนอื่นทำต่อ · ลืมว่าทำอะไรไว้

---

## สรุปสั้นที่สุด (อ่านแค่นี้ก่อนก็ได้)

**คอมพัง = เว็บไม่ดับ** เว็บรันอยู่บนคลาวด์ (Railway) ไม่ได้รันในคอมส่วนตัว
ทีมยังใช้งานได้ตามปกติ ข้อมูลไม่หาย โค้ดไม่หาย (อยู่บน GitHub)

**สิ่งเดียวที่หายคือ "โต๊ะทำงาน"** — เครื่องมือที่ใช้แก้โค้ด ซึ่งติดตั้งใหม่ได้ในครึ่งชั่วโมง

---

## ส่วนที่ 1 — ของสำคัญอยู่ที่ไหนบ้าง

| สิ่งของ | เก็บไว้ที่ | เครื่องพังแล้วหายไหม |
|---|---|---|
| โค้ดทั้งหมด | GitHub: `Coachmeow/cps-eco-planning` | ไม่หาย |

## ส่วนที่ 2 — ขั้นตอนกู้คืนบนเครื่องใหม่

### ขั้นที่ 1 — ติดตั้งโปรแกรม 3 ตัว

| โปรแกรม | ทำหน้าที่อะไร | โหลดจาก |
|---|---|---|
| **Git** | ดึงโค้ดจาก GitHub ลงเครื่อง และส่งกลับขึ้นไป | git-scm.com |
| **Node.js** (เวอร์ชัน LTS) | ตัวรันภาษาที่เว็บนี้เขียนด้วย | nodejs.org |
| **Claude Code** | AI ผู้ช่วยเขียนโค้ด | claude.com/claude-code |

*ทำไปทำไม:* Git คือตัวเชื่อมกับ GitHub · Node.js จำเป็นสำหรับตรวจสอบโค้ดก่อนส่งขึ้นระบบจริง ·
Claude Code คือผู้ช่วยที่ใช้แก้โค้ดโดยไม่ต้องเขียนเองทั้งหมด

**แนะนำเพิ่ม:** Visual Studio Code (โปรแกรมเปิดดูไฟล์โค้ด) — ไม่บังคับ แต่ช่วยให้เห็นภาพรวมง่ายขึ้น

### ขั้นที่ 2 — ดึงโค้ดลงเครื่อง

เปิด **Terminal** (บน Windows ใช้ Git Bash หรือ PowerShell) แล้วพิมพ์:

```bash
cd D:/
git clone https://github.com/Coachmeow/cps-eco-planning.git
cd cps-eco-planning
```

ระบบจะถามชื่อผู้ใช้และรหัส GitHub — ใส่ **username** และ **Personal Access Token**
(ไม่ใช่รหัสผ่านปกติ ดูวิธีสร้างที่ส่วนที่ 4)

*ทำไปทำไม:* เป็นการดาวน์โหลดโค้ดทั้งหมดพร้อมประวัติการแก้ไขทุกครั้งที่ผ่านมา
หลังจากนี้เครื่องใหม่จะมีทุกอย่างเหมือนเครื่องเดิม

### ขั้นที่ 3 — ติดตั้งส่วนประกอบของโปรเจกต์

```bash
npm install
```

*ทำไปทำไม:* โปรเจกต์นี้ใช้ไลบรารีจากคนอื่นหลายร้อยตัว (เช่น ตัวสร้าง PDF ตัววาดกราฟ)
ซึ่งไม่ได้เก็บใน GitHub เพราะไฟล์ใหญ่มาก คำสั่งนี้ดาวน์โหลดมาให้ครบตามรายการในไฟล์ `package.json`
ใช้เวลาประมาณ 2–5 นาที

### ขั้นที่ 4 — สร้างไฟล์ตั้งค่าในเครื่อง

สร้างไฟล์ชื่อ `.env` ในโฟลเดอร์โปรเจกต์ ใส่ข้อความนี้:

```

```

*ทำไปทำไม:* โปรแกรมต้องเห็นตัวแปรนี้ถึงจะยอมทำงาน แต่**ตั้งใจใส่ค่าหลอก**
เพราะเราจะ**ไม่ต่อฐานข้อมูลจริงจากเครื่องส่วนตัว** (กันเผลอลบข้อมูลของทีม)
ฐานข้อมูลจริงเชื่อมต่อจากฝั่ง Railway เท่านั้น

**ประโยคที่ใช้เริ่มได้เลย:**

> "อ่านไฟล์ใน docs/ ก่อน แล้วสรุปให้ฟังว่าโปรเจกต์นี้คืออะไร ทำอะไรไปแล้วบ้าง"

## ส่วนที่ 3 — งานประจำที่ต้องทำเป็น

### แก้โค้ดแล้วส่งขึ้นระบบจริง

```bash
git add -A
git commit -m "อธิบายสั้นๆ ว่าแก้อะไร"
git push origin master
```

*ทำไปทำไม:*
- `git add -A` — เลือกไฟล์ที่แก้ทั้งหมดเข้าคิว
- `git commit` — บันทึกเป็นจุดเช็คพอยต์ พร้อมคำอธิบาย (ย้อนกลับมาจุดนี้ได้ตลอด)
- `git push` — ส่งขึ้น GitHub

> ⚠️ **`git push` = ขึ้นระบบจริงทันที** Railway จะเห็นโค้ดใหม่แล้ว deploy ให้เองภายใน 2–3 นาที
> ทีมที่กำลังใช้งานอยู่จะเห็นของใหม่หลังรีเฟรชหน้าเว็บ

### ดูว่าตอนนี้แก้อะไรค้างไว้

```bash
git status
```

### ดูประวัติการแก้ไขที่ผ่านมา

```bash
git log --oneline -20
```

### ย้อนกลับเมื่อของใหม่พัง

มีจุดย้อนกลับที่ทำเครื่องหมายไว้ (ดูรายละเอียดใน `docs/context/02-deploy-and-auth.md`)

```bash
git log --oneline -20          # หาว่าจะย้อนกลับไปจุดไหน
git revert <รหัส commit>        # ยกเลิกการแก้ครั้งนั้น (ปลอดภัย ไม่ลบประวัติ)
```

> แนะนำให้ใช้ `git revert` มากกว่า `git reset --hard` เพราะ revert ไม่ลบประวัติ ย้อนกลับได้อีก

## ส่วนที่ 4 — เรื่องบัญชีและรหัสผ่าน

### GitHub Personal Access Token

GitHub ไม่ให้ใช้รหัสผ่านปกติในการ push แล้ว ต้องใช้ **Token** แทน

**วิธีสร้าง:** GitHub → คลิกรูปโปรไฟล์ → Settings → เลื่อนล่างสุด **Developer settings**
→ Personal access tokens → Tokens (classic) → **Generate new token**
→ ติ๊กสิทธิ์ `repo` → ตั้งวันหมดอายุ → Generate → **คัดลอกเก็บทันที** (ปิดหน้าแล้วดูซ้ำไม่ได้)

**เก็บ Token ให้ปลอดภัย:** ให้ Windows จำให้แทนการฝังไว้ในโปรเจกต์

```bash
git config --global credential.helper manager
```

หลังตั้งค่านี้ พิมพ์ Token ครั้งเดียวตอน push ครั้งแรก Windows จะจำให้เอง

> 🔴 **ห้ามใส่ Token ลงไปใน URL ของ remote โดยตรง** (แบบ `https://ชื่อ:ghp_xxxx@github.com/...`)
> เพราะจะถูกเก็บเป็นข้อความธรรมดาในไฟล์ตั้งค่าของโปรเจกต์ ใครเปิดเครื่องได้ = แก้โค้ดเว็บได้

**ตรวจว่าตอนนี้ปลอดภัยไหม:**

```bash
git remote -v
```

ถ้าเห็นตัวอักษรยาวๆ ขึ้นต้นด้วย `ghp_` หรือ `github_pat_` แสดงว่า Token ถูกฝังอยู่ →
ให้เข้า GitHub ไป **Revoke** ตัวนั้นทิ้ง สร้างใหม่ แล้วแก้ remote ให้เหลือแค่:

```bash
git remote set-url origin https://github.com/Coachmeow/cps-eco-planning.git
```

### รหัสเข้าเว็บ

บัญชีผู้ดูแลระบบตั้งค่าเริ่มต้นไว้ในไฟล์ `scripts/bootstrap.cjs`
ถ้าลืมรหัส เข้าไปดูในไฟล์นั้น หรือแก้แล้ว deploy ใหม่เพื่อรีเซ็ต

## ส่วนที่ 5 — สิ่งที่ต้องระวัง

| ห้ามทำ | เพราะอะไร |
|---|---|
| รัน `npx prisma db seed` กับข้อมูลจริง | ล้างฐานข้อมูลทั้งหมด |
| รัน dev server ต่อฐานข้อมูล production | เสี่ยงแก้/ลบข้อมูลของทีมโดยไม่ตั้งใจ |
| `git push --force` | ลบประวัติการทำงานบน GitHub |
| ลบ service บน Railway | ข้อมูลหายถาวร |
| แก้โค้ดตรงบน GitHub เว็บไซต์ | ข้ามการตรวจสอบ อาจทำให้เว็บล่ม |

**ก่อน push ทุกครั้ง:** รัน `npx tsc --noEmit` และ `npx next build` ให้ผ่านก่อนเสมอ

## ส่วนที่ 6 — ถ้าติดปัญหา

1. **เว็บล่มหลัง deploy** → Railway → แท็บ **Deployments** ดู log ว่า error อะไร
   หรือกด **Redeploy** เวอร์ชันก่อนหน้าเพื่อกลับไปใช้ของเดิมก่อน
2. **ลืมว่าทำอะไรไว้** → เปิด Claude Code แล้วสั่ง: *"อ่าน docs/ แล้วสรุปสถานะโครงการ"*
3. **โค้ดพังไม่รู้สาเหตุ** → `git log --oneline -20` หา commit ล่าสุดที่ยังดี แล้ว `git revert`
4. **ตัวแปรลับหาย** → Railway → Variables ตั้งใหม่ตามตารางใน `docs/context/02-deploy-and-auth.md`

## ภาคผนวก — คำศัพท์

| คำ | หมายถึง |
|---|---|
| **Repository (repo)** | โฟลเดอร์โครงการที่เก็บบน GitHub พร้อมประวัติการแก้ไขทั้งหมด |
| **Commit** | จุดบันทึกการแก้ไขครั้งหนึ่ง เหมือนเซฟเกม ย้อนกลับมาได้ |
| **Push** | ส่งการแก้ไขจากเครื่องขึ้น GitHub (โครงการนี้ = deploy ขึ้นระบบจริงด้วย) |
| **Clone** | ดาวน์โหลดโครงการทั้งหมดจาก GitHub ลงเครื่อง |
| **Deploy** | นำโค้ดใหม่ขึ้นเซิร์ฟเวอร์ให้ผู้ใช้จริงเห็น |
| **Environment variable** | ตัวแปรลับ (รหัส/ที่อยู่ฐานข้อมูล) เก็บแยกจากโค้ด |
| **Migration / db push** | ปรับโครงสร้างตารางในฐานข้อมูลให้ตรงกับโค้ด |
| **Branch `master`** | เส้นทางหลักของโค้ด — ตัวที่ใช้ deploy จริง |
